# 决策记录（ADR）

每条决策一个编号。改决策 = 新增一条 ADR 并标注取代关系，不要直接改历史。

当前元数据功能边界以 ADR-030 为准；早期 ADR 中的编辑器、查源和格式扩展计划保留为历史记录。
备份范围及“我的图书馆”的数据来源以 ADR-031 为准；早期 ADR 中的 JSON 备份和本地书架安排保留为历史记录。
我的书单的设置入口以 ADR-084 为准，四封面卡片沿用 ADR-082；详情内加入及新建书单见 ADR-094–096/100，下载记录入口以 ADR-049 为准。图书与自有书单的图片分享见 ADR-101。
「延展书单」及限定书页读取已按 ADR-099 取消，ADR-097/098 仅保留历史记录。
详情页收藏写入以 ADR-033 为准。
详情页胶囊和作者行字号以 ADR-087 为准，出版信息与顶栏操作见 ADR-088/092，在线预览的实时链接和会话边界见 ADR-089/091，简介布局及图书评论见 ADR-093/095/096。
图书网格的封面与书名显示以 ADR-034 为准。
自动网格密度、阅读首页及缺图书封以 ADR-036 为准。

## ADR-001：Kotlin 原生重写，不打包 Go CLI

**状态**：接受

**背景**：`heartleo/zlib` 是 Go CLI，没有公开 API；TUI 与终端能力无法直接复用到 Android。

**决策**：用 Kotlin 重写 EAPI 客户端与业务层；不采用 gomobile、不嵌入 Go 二进制、不调用 CLI 子进程。

**后果**：协议逻辑需要重新验证；但 UI、存储、后台下载、SAF 都是原生体验，包体小，可维护。

---

## ADR-002：只做 Z-Library 镜像，不做多书源

**状态**：接受

**背景**：多书源（Anna's Archive、Gutenberg、IA）协议、合法性和元数据模型完全不同。

**决策**：v1 只实现 `ZlibSource`；保留 `BookSource` 接口作为未来扩展点，不实现其它源。

**后果**：范围可控；未来接多书源需要新的数据模型和合规评估。

---

## ADR-003：范围 A+B+D，不做 C；Kindle 用系统分享替代

**状态**：接受

**背景**：CLI 的微信读书导入（扫码 + COS 上传）与 Kindle SMTP 都是独立子系统。

**决策**：
- A 核心 + B 元数据 + D 书单/历史删除。
- 不做微信读书导入 API、不做 Kindle。
- “打开书” = `ACTION_SEND` 分享给阅读器/微信读书。
- E 只保留 JSON 备份/恢复；更新检查放 v1.1。

**后果**：v1 不依赖微信 SDK/SMTP；分享面板的可用性取决于用户安装的 App。

## ADR-004：不做内置阅读器

**状态**：接受

**背景**：EPUB/PDF 阅读器是独立产品，涉及排版、翻页、目录、进度、字体。

**决策**：v1 只下载和分享；书架记录“已下载”，不记录阅读进度。

**后果**：用户需要外部阅读器；未来要做阅读器时另立模块和 ADR。

## ADR-005：书库按 CLI 语义（C1）

**状态**：接受

**背景**：CLI 的“书库”实际是已下载 + 收藏 + 历史 + 书单；本地文件只用于 `meta`。

**决策**：C1。不做任意本地文件导入、重复检测、系列、阅读进度。本地文件仅通过元数据编辑入口访问。

**后果**：数据模型简单；用户不能把任意本地书加入书架。

## ADR-006：SAF 作为唯一下载落盘方式

**状态**：接受

**背景**：MediaStore 直写 Downloads 对 `.part`、续传、改名不友好；应用私有目录用户找不到。

**决策**：用户通过 `ACTION_OPEN_DOCUMENT_TREE` 选一次目录（默认提示 `Download/ZLib`），持久化 URI 权限；`.part` 同目录，完成后 rename；不支持 rename 时 copy+delete。

**后果**：首次使用多一步；换目录需要重新授权；不申请 legacy 存储权限。

## ADR-007：minSdk 33 / targetSdk 37 / compileSdk 37.2

**状态**：接受

**背景**：Miuix glass/blur 依赖 API 31 的 RenderEffect；`miuix-blur` 的 manifest 实际要求 **minSdk 33**。用户接受较新设备范围与性能风险。

**决策**：minSdk 33，targetSdk 37，compileSdk 37.2，build-tools 37.0.0，JVM 21。

**后果**：放弃 Android 13 以下设备；省掉大量旧行为分支；玻璃效果可用。

## ADR-008：Miuix 0.9.5-beta03，全 Android 模块

**状态**：接受，带风险

**背景**：glass/blur 只在 0.9.5-beta 线；稳定 0.9.4 没有 glass。beta03 绑定 Compose 1.13.0-rc01 与 AGP 9.5.2。

**后果**：接受 RC Compose 与 beta API 变更；升级需单独验证；玻璃效果提供设置开关与低端机降级。

## ADR-009：组件化模块图与 miuix-nav

**状态**：接受

**模块**：`:app` + `:core:{common,model,designsystem,network,database,data}` + `:feature:{search,detail,downloads,library,account,settings,metadata,booklists}`。

## ADR-010：Hilt + Room + KSP，1 天 spike，失败回退手写 DI

**状态**：接受（Hilt/KSP spike 已通过，Room 待 v0.4 接入）

**背景**：AGP 9.5.2 + Kotlin 2.4.21 + KSP 2.3.12 是前沿组合；Room+KSP 有本机先例，Hilt 未验证。

**决策**：先按 Hilt + Room + KSP 搭；第一天做最小 spike（Application + 一个 ViewModel + 一个 DAO）。失败则回退 `AppContainer` 构造注入，Room 保留。禁止两套 DI 混用。

**验证（2026-11-21）**：`:app` 与 `:core:data` 已启用 Hilt 2.60.1 Gradle 插件 + KSP 2.3.12，`@HiltAndroidApp`、`@AndroidEntryPoint`、跨模块 `@Inject`/`@Provides`、`@HiltViewModel` 均编译通过并在真机启动；`SecretCipher`、DataStore、Repository 由 Hilt 装配。Room 在 v0.4 下载队列落地时再加，不自造第二套 DI。

**后果**：Hilt 失败会多一天；回退后 ViewModel 工厂需要手写。当前无需回退。

## ADR-011：裸 OkHttp + 前台 Service 下载

**状态**：接受

**背景**：EAPI 需要动态域名、Cookie/remix 头、表单编码、错误 envelope、跨域重定向剥离凭据；Retrofit 的动态 baseUrl 反而绕。

**决策**：OkHttp + kotlinx.serialization + 自定义 `EapiClient`。下载用前台 `dataSync` Service + Room 队列，顺序 1，Range 续传；WorkManager 只做失败重试/清理。

**后果**：网络层代码量略多；但行为完全可控，测试用 MockWebServer。

## ADR-013：CLI 同款域名策略

**状态**：接受

## ADR-018：服务端状态与本地文件语义

**状态**：接受

**决策**：
- 收藏/历史以服务端为准；启动/下拉刷新。

## ADR-019：会话加密使用 Android Keystore + DataStore 自实现

**状态**：接受

**背景**：`androidx.security:security-crypto` 长期停留在 alpha 且已弃用；只需要保存一个会话 blob。

**决策**：`SecretCipher` 接口 + `KeystoreSecretCipher`（AES-256-GCM，密钥别名 `zlib.session.v1`，IV 前置）；密文 Base64 后写入 Preferences DataStore。密钥失效/解密失败视为未登录，不崩溃。

**后果**：无额外依赖；单元测试通过 `SecretCipher` 假实现覆盖 `SessionManager`，Keystore 本身留仪器测试。会话不参与备份（`allowBackup=false` + data extraction rules）。

## ADR-023：下载先解析 JSON `file.downloadLink`

**状态**：接受（2026-11-22 实测）

**背景**：`/eapi/book/{id}/{hash}/file` 在 z-lib.gl 返回 `200 application/json`：`{"success":1,"file":{"downloadLink":"…","allowDownload":true,…}}`，而不是文档假设的 302。直接按文件流写入会把 477 字节 JSON 当成 EPUB 并标为完成。

**决策**：下载先请求 file 端点；若响应为 JSON，解析 `file.downloadLink`（兼容 `file` 字符串/对象、`downloadUrl`/`url`/`link`），再对链接发第二个 GET，携带 Range；仍走凭据剥离拦截器。`allowDownload=false`、无链接或响应不是 HTTPS 均失败。写入前做 EPUB/PDF/FB2 魔数校验，失败不标完成。

**后果**：适配两种镜像行为；JSON 错误页不再污染书架。签名链接只存在于内存，不落盘、不记日志。

## ADR-021：分享直接使用 SAF 文档 URI

**状态**：接受

**背景**：下载只写用户选择的 SAF 目录树（ADR-006）。`FileProvider` 只能暴露应用私有目录，把 SAF 文件复制到 cache 再分享会多一次 IO 和一份临时副本。

**决策**：`ACTION_SEND` 的 `EXTRA_STREAM` 直接使用 SAF `content://` URI，并加 `FLAG_GRANT_READ_URI_PERMISSION`；不引入 `FileProvider`。

**后果**：接收方可直接读取文档；无临时文件与清理逻辑。若后续需要分享应用内生成的非 SAF 文件（如改好的元数据缓存），再单独加 `FileProvider`。

## ADR-022：Room 列名使用 Kotlin camelCase

**状态**：接受

**背景**：`docs/ARCHITECTURE.md` 的 schema 用 snake_case 示例；Room 默认按属性名生成列名。

**决策**：v1 schema 直接用 camelCase 列名（`bytesWritten`、`localUri` 等），表名仍为 `books` / `download_queue`；查询与迁移以 `core/database/schemas/1.json` 为准。

**后果**：少一层 `@ColumnInfo` 噪声；文档中的 snake_case 仅作概念示意。

## ADR-024：热门作为首页，搜索使用独立路由

**状态**：接受；替代 ADR-009 中首个 tab 为搜索的决定。

**决策**：主导航为热门 / 书架 / 下载 / 我的。热门页展示 EAPI 热门与推荐，搜索从热门页的顶部按钮进入独立路由，不占底部 tab。热门、搜索结果和书架共用大封面网格。

**布局**：沿用 Miuix 示例的滚动布局；顶栏渐进模糊、图标按钮和底栏共享页面采样层，内容使用实测栏高作为滚动内边距。关闭玻璃效果时保留同样的页面背景和导航入口。

## ADR-025：三栏主导航、独立下载管理和分组书架

**状态**：接受；替代 ADR-024 的底部导航安排，保留热门首页与独立搜索。

**决策**：底部仅保留热门 / 书架 / 设置。首页顶栏由左到右提供搜索、下载管理两个操作。下载管理只展示任务、进度与记录；下载目录、账号、域名及外观集中到分组设置。

**书架**：已下载来自 Room；收藏和下载历史从已记载的 EAPI 分页读取，按分组保留滚动位置，支持刷新。收藏和历史本次只读，不把远端记录当成已下载文件，也不改变本地删除的语义。

## ADR-026：固定深浅色方案，默认跟随系统

**决策**：停止使用壁纸动态取色。浅色使用 `#F5F5F5` 页面、`#FFFFFF` 卡片和黑色主文字；深色使用 `#000000` 页面、`#202022` 卡片和白色主文字。设置通过 Miuix 弹出菜单选择跟随系统、浅色或深色；旧版只有取色开关时，升级后默认跟随系统。

## ADR-027：玻璃外观跟随 Miuix 示例的静态主题

**背景**：顶栏只放大按钮直径、不调整继承的玻璃形状，会使轮廓偏方。额外绘制实色按钮底和覆盖导航选中颜色也会改变示例的玻璃观感。

**决策**：保留 ADR-026 的页面、卡片和主文字颜色，其余以 Miuix 内置浅色/深色方案为基础。玻璃使用同版本示例的深浅材质样式及中等边缘高光。顶栏图标使用库的 44 dp 原生尺寸与同半径圆形，不绘制额外底色；列表滚入顶栏时按 Miuix 默认行为浮起玻璃材质。底栏保留原生高度与指示器，只收窄三项的布局宽度。

## ADR-028：玻璃是默认界面，不再提供开关

**状态**：接受；取代 ADR-008 和 ADR-024 中允许手动关闭玻璃的决定。

**决策**：支持玻璃的设备始终使用玻璃导航，不读取旧版 `glass_enabled`，也不提供设置开关。保留设备不支持材质或低内存时的自动降级，确保导航入口和安全区不变。

## ADR-029：玻璃弹层与书架顶栏共用设计系统

**状态**：接受；细化 ADR-025 的书架分组与 ADR-026 的外观菜单。

**决策**：书架分组使用 `GlassSegmentedTabRow`，置于 `GlassTopAppBar` 内，由列表滚动驱动材质，内容内边距包含分组栏的实测高度。搜索筛选使用 `GlassBottomSheet`，应用内的确认框复用 `GlassDialog`，外观模式使用原生展开／收起动画的 `GlassDropdownPreference`。弹层与导航使用一致的中等级 Bloom Stroke（`MiddleLight` / `MiddleDark`），不另增设置项。

**实现边界**：导航仍采样滚动内容；弹层单独采样含顶栏和底栏的完整页面，通过外层 `Scaffold` 展示，避免采到自身和遮罩。设备不支持玻璃时保留实色控件和原有交互。

## ADR-030：取消本地电子书元数据编辑计划

**状态**：接受（2026-11-22）；取代 ADR-014，以及 ADR-003 的 B 元数据范围、ADR-005 的本地元数据编辑入口、ADR-009 的 `:feature:metadata` 模块安排。

**背景**：本地元数据编辑需要维护多种电子书格式的解析、封面处理、第三方查源和 SAF 安全写回。这是一套独立于核心 EAPI 的文件编辑工具，目前仅有计划和空模块。用户决定缩减范围，将开发与维护投入集中到浏览、下载和书架。

**决策**：

- 取消 EPUB/FB2/DOCX 的本地元数据读取与编辑、逐字段确认、在线查源、嵌入封面、编辑器重命名及安全写回计划。
- 删除 v0.6 元数据阶段和 v1.1 的 MOBI/PDF/Goodreads 元数据扩展，不自动延期到后续版本；未来重启需另立 ADR。
- 移除尚未实现的 `:feature:metadata` 空模块，以及文档中的编辑路由、仓储和测试要求。
- 详情页继续展示 EAPI 返回的书名、作者、ISBN、封面等图书信息；下载格式支持、下载文件命名与清洗、SAF 落盘和系统分享继续保留。
- v1 范围收敛为 A 核心、D 书单/历史删除和 E 中的 JSON 备份/恢复；继续不做任意本地文件导入。

## ADR-031：取消应用备份，我的图书馆以 Z-Library 云端为准

**状态**：接受（2026-11-22）；取代 ADR-003 的 E 备份范围、ADR-030 的 JSON 备份交付项、ADR-005 的本地书库范围、ADR-018 的可选联动删除本地文件安排，以及 ADR-025 中书架“已下载”来自 Room 的决定。

**背景**：用户只需要访问 Z-Library 账号的“我的图书馆”，其中书单、收藏和已下载记录使用网站的云端数据。独立维护本地书库和备份文件会增加配置与维护成本，偏离客户端定位。当前代码已接入云端收藏和下载记录，但书架“已下载”仍是本机文件，书单尚未接入。

**决策**：

- 取消应用内 JSON 备份/恢复及设置、书库、书单的本地导入导出计划，不自动延期；登录需要的 Cookie 导入继续保留。
- 书架对应 Z-Library 的“我的图书馆”，目标分组为云端已下载、收藏和书单；其内容、归属及变更结果以服务端为准，不创建独立的本地书单或收藏标记。
- 已确认的 `/eapi/user/book/downloaded` 是账号下载记录，作为云端“已下载”的接入依据。它不证明本机已有文件，也不证明客户端已获得网站所有图书馆分组的协议。
- 云端书单的读取、分页、权限和详情先验证 EAPI 并补入 `docs/EAPI.md`，再接入 UI；创建/编辑仍待实测。未确认接口时保留待办，不猜测路径、不抓 HTML、不以本地书单代替。
- Room 继续保存下载队列、续传进度和本机文件 URI，也可保存按账号隔离、可从云端重建的缓存；这些本地记录不决定云端图书馆内容。
- 本机文件的分享/删除归下载管理，取消独立本地书库的搜索/排序计划；删除本机文件与删除云端下载记录各自独立。云端记录存在时也不能直接显示本机可分享，必须检查本机文件。
- 保留 `allowBackup=false` 和禁止系统数据迁移的安全配置；登录后重新从云端读取图书馆，下载目录仍需 SAF 授权，本机文件不由云端记录自动恢复。

**后果**：v1 聚焦核心 EAPI 与云端图书馆，不交付备份。现有书架本地页和文件操作需迁移至下载管理；这是后续实现任务，本条及配套文档不表示 UI 迁移或书单接口已完成。

## ADR-032：书架只保留收藏和书单，下载内容归下载管理

**状态**：接受（2026-11-22）；取代 ADR-031 的三个书架分组，以及 ADR-025/ADR-029 中“已下载/收藏/历史”的分组安排。

**背景**：用户要求书架顶部对应云端“我的图书馆”的收藏和书单。现有“历史”实际读取 `/eapi/user/book/downloaded`，是云端下载记录，容易与浏览历史及本机文件混淆。

**状态**：接受（2026-11-22）；按用户要求，细化 ADR-042 的下载按钮行为。继续只使用 EAPI。

**决策**：点击“下载图书”先打开设计系统玻璃底部菜单，并请求 `GET /eapi/book/{id}/{hash}/formats`。菜单显示服务端返回的全部有效格式条目及文件大小，使用各条目的独立 `id:hash` 下载，不用当前图书引用拼出另一种格式，也不在本地转换。相同格式但引用不同的文件不合并；当前详情已确认的格式保留一项，按引用去重。即使只有一种格式，也必须由用户点选后入队。

## ADR-060：下载文件身份、续传校验与目录切换保护

**状态**：接受（2026-11-23）；用户确认实施下载可靠性调研中的优化，细化 ADR-006/011/045/049/050/051。

## ADR-065：内置域名 zlib.re、体检顺序与重定向目标发现

**状态**：接受（2026-11-23）；保留 `zlib.re` 与匿名目标发现，体检顺序由 ADR-066 更新，以下自动授信与切换规则为历史记录，已由 ADR-102 取代。用户当时要求先检查重定向目标再使用，并把大陆可用域名排在前列。

**决策**：`DomainPolicy.BUILT_IN_SUFFIXES` 增加 `zlib.re`；`DEFAULT_PROBE_HOSTS` 改为 9 项，顺序即故障切换优先级，前三项为 `zlib.bz`、`zlib.re`、`z-library.im`（大陆环境可用域名排前），其余沿用原列表（**顺序部分与 `zlib.re` 之外的内置条目已由 ADR-066 取代**）。用户镜像与自动发现目标都只信任精确 host，不扩展到子域，也不改变 §3.2 的其他限制。

内置域名允许 301/302/307 跳到 allowlist 之外的 host（实测 `z-lib.by → zh.z101.by`；`zlib.re` 当日先是 `zh.us101.ru`、稍后变为 `z-lib.by`，跳转目标本身会变）。跳转目标按以下规则处理：跟随跳转链时一律不携带 Cookie／`remix-userid`／`remix-userkey`；对目标 host 的 `/eapi/info/domains` 重新探测，最多 3 跳，且总是把路径重写为该端点；只有 HTTP 200、`success:1` 且 `domains` 数组含已知域名家族时才校验通过。校验通过后把精确目标 host 记入会话内运行时 allowlist 并作为当前域名使用，原域名卡片显示“重定向 → 目标”；未通过（HTML 验证、513/517、非 2xx、超时、无已知域名家族）时仅在原域名上报告失败，绝不使用该目标，也不向其发送任何凭据。

已校验目标持久化到 DataStore `discovered_hosts`，仅用于下次冷启动的无凭据复检；复检通过才恢复信任，失败则移除（当前域名与锁定域名除外，避免用户看不到状态）。发现目标排在数据类末尾参与后续体检，不写入用户镜像列表，删除镜像不影响它们。探测目标是独立的无凭据客户端请求，凭据剥离与重定向拦截仍以运行时 allowlist 为准；因此本 ADR 不放松 §3.3 的“凭据绝不发给 allowlist 之外的 host”，只是把校验通过的精确 host 纳入运行时 allowlist。

限制：本 ADR 不承诺跳转目标永远可用或一定属于官方；用户镜像、账号切换及真实跳转先后验收仍需独立真机确认。

## ADR-066：z101.by 纳入内置清单与探测顺序按真实可用性重排

**状态**：接受（2026-11-23）；用户确认 `z101.by` 在浏览器中可用，并要求据此调整内置域名与顺序。

**决策**：`BUILT_IN_SUFFIXES` 增加 `z101.by`（官方 `z-lib.by` 的 301 目标 `zh.z101.by` 所在域，裸 host 实测 `/eapi/info/domains` 返回 `success:1`，`/eapi/book/most-popular` 有真实书目）。ADR-065 的 9 项顺序与“前三项”条款被本条取代。

## ADR-067：所有底部短提示统一为系统 Toast，移除 Snackbar

**状态**：接受（2026-11-23）；用户要求把书架本机文件删除后的底部提示等所有“跳跳式”底部提示改成检查更新那种 Toast。

**决策**：设计系统只保留一种短提示——`ZlibToastHost`（`android.widget.Toast`，`LENGTH_SHORT`，无按钮、无关闭、自动消失）。`ZlibSnackbar.kt`、`ZlibPage`/`ZlibOverlayHost` 的 `snackbarHost` 插槽及 Miuix `SnackbarHost` 依赖全部删除；feature 不得再自建底部提示条或顶部“提示卡片”。提示仍是一次性事件，不做可重放状态。

`ZlibToastHost` 提供两种入口：`ZlibToastHost(messages: Flow<String>, key)` 用于已有事件流的页面，新增 `rememberZlibToastHostState()` + `state.showMessage(text)` + `ZlibToastHost(state)` 用于即时调用（链接无法打开、Intent 无接收应用、安装失败等）。同一页面只允许一个 Toast 宿主，避免两条通道各弹一次；`key`（会话代次、当前下载目录等）变化时取消未消失的提示，页面退出时 `onDispose` 取消。

覆盖范围：云端下载记录删除成功、手动检查已是最新版、书架本机文件删除成功、打不开/分享不了文件、无法访问下载目录、账号与域名页操作结果、关于页链接失败、更新包安装失败。删除失败等需要重试或二次确认的错误仍留在确认面板内，不改成 Toast；分页/加载失败仍用列表内 `ZlibStateCard` 与重试，不改成 Toast。

理由：系统 Toast 与平台行为一致、不遮挡列表底部操作、实现简单；Snackbar 在玻璃界面上会与底部导航和 SAF 返回冲突，且此前已出现两套并存。限制：Toast 无法承载按钮，故凡需要用户决策的反馈不得走 Toast；系统 Toast 文案长度与显示位置由系统决定，不保证所有 ROM 一致。

## ADR-079：复用现有会话，只读接入「我的书单」

**状态**：接受（2026-11-24）；按用户要求恢复云端书单浏览，取代 ADR-031/032/051 中书单只限 EAPI 或移除的决定。书架内的书单分组后被 ADR-080 移到独立主导航，其余决定继续有效。

**决策**：书架改为「本机 / 收藏 / 书单」，首次仍默认本机。「书单」只读展示当前账号自己的书单，显示名称及服务端返回的图书数量；点入独立页面，复用封面网格、图书详情导航和自动分页。列表和单内图书支持下拉刷新与失败重试。本次不接入创建、编辑、删除、加书、公开书单或评论，不维护本地书单。书单分组后按 ADR-080 移到独立主导航；推荐书单与匿名公开单内读取也由 ADR-080 追加。

在现有 `:feature:library` 内实现，不恢复独立书单模块。图书服务仍以 EAPI 为主，本 ADR 只接入 `EAPI.md` §2.10 中当前账号书单列表和“我的”单内读取两类只读 PAPI JSON 调用；ADR-080 再追加推荐与匿名公开单内读取。复用当前会话的 `remix_userid` / `remix_userkey`，按 PAPI 用法只发送这两个 Cookie，不发送密码、不另行登录、不复制其它 Cookie；只发送到会话指定的当前受信任 HTTPS 主机，不跟随重定向或换域。PAPI 拒绝登录不使 EAPI 会话失效；不抓 HTML、不绕过验证。书单和图书数据仅保存在当前会话内存；进入单内页先核对当前账号书单归属，账号或域名变化时取消旧请求并清空旧结果。

**依据和验证边界**：ZlibraryKO 将 EAPI 登录返回的 ID/key 与其他登录来源归一化，以同一对 Cookie 读取 PAPI 书单；Python 客户端和中文协议笔记独立记录相同书单端点及响应结构。2026-11-24 四个镜像匿名读取书单列表均返回 JSON HTTP 401，确认不是公开接口；这不等于已验证本项目任一真实登录态。自动测试应覆盖会话复用、错误、分页和隔离；真实账号是否可读以实际镜像验收为准。

## ADR-080：书单成为独立主导航，分为「我的／发现」

**状态**：接受（2026-11-24）；用户确认 ADR-079 的书单能正常显示，要求将书单移到底栏并增加发现分组。

**决策**：底栏依次为「发现／书架／书单／设置」。书架只保留「本机／收藏」；书单沿用玻璃顶栏分组「我的／发现」，首次默认「我的」，两个分组分别保存列表与滚动位置。保留原私有书单归属校验、刷新、分页与 EAPI 图书详情。

**依据和验证边界**：zlibx 的公开目录与搜索仍是 HTML，推荐接口偶尔返回 `html` 数组；本项目只接入后者。2026-11-24 对 `zh.z-lib.by`、`zlib.bz` 匿名 POST `/papi/booklist/get-from-category` 均返回 HTTP 200、`application/json`、`success:1` 但无 `html` 字段，因此推荐为空时只能以浏览器目录兜底，不能宣称所有镜像都会返回推荐；匿名 POST 公开书单 `2177510` 的 `get-books/1` 与 `/2` 均返回 20 本及下一页，确认公开单内读取可用。推荐列表的真实非空结果仍需有效会话或服务端实际返回后验收。

## ADR-089：按当前镜像实时获取在线预览链接

## ADR-090：阅读页仅在服务器返回的受信主机使用当前会话

**状态**：已被 ADR-091 取代（2026-11-25）。

**决策**：预览页继续原样使用当前会话镜像的 EAPI 详情响应中的 `readOnlineUrl`，不拼接、不改写主机、路径或签名。只在该服务器返回并通过 HTTPS 校验的阅读主机及其对应的裸镜像主机上，临时写入当前会话的 `remix_userid` / `remix_userkey` Cookie；WebView 的其他第三方 Cookie 仍关闭，外部主机仍被拦截。Cookie 只在预览页生命周期内存在，进入前清空 WebView Cookie 存储，离开预览时再次清除，不写 URL、导航参数、剪贴板或持久存储。会话或镜像变化销毁旧网页。该行为不恢复网页登录，不抓取 HTML 数据，不扩大域名 allowlist。

**后果**：阅读器可以用当前账号完成自身鉴权并读取文件；预览链接仍完全来自当前镜像的实时详情。不能把 `support@z-lib.bz` 等站方固定支持邮箱误判为实际加载域名。

## ADR-091：在线预览使用详情实时链接且不限制阅读器资源域名

**状态**：接受（2026-11-25）；取代 ADR-090。用户明确要求预览“不要任何白名单，不要任何限制”。真机日志显示顶层阅读页已返回 200、会话 Cookie 已写入且 `missing=false`，但正文仍停在 `Loading reader…`；真正失败点是阅读器静态资源 `reader-content-alp-01.cdn-zlib.sk` 被按主机名拦截并返回 403，而不是登录态或阅读链接主机。

**决策**：预览页只使用当前镜像 EAPI 详情实时返回的 `readOnlineUrl`，原样保留其主机、路径、查询参数与签名，不拼接、不改写、不缓存，也不根据当前域名猜测阅读主机。不校验阅读器主机是否属于某个镜像，不建立页面或资源 CDN 的域名白名单，不通过 `shouldInterceptRequest` 拦截阅读器请求。进入预览前清空 WebView Cookie，预览期间不注入 `remix_userid` / `remix_userkey` 或任何账号 Cookie，退出再次清空；公开阅读链接在未登录和已登录状态下都可打开。WebView 仍只接受 HTTPS 顶层链接，禁止访问本地文件与内容 URI，不注册 JavaScript Bridge，不注入应用脚本，不绕过验证、不抓取 HTML 提取图书数据，也不恢复网页登录。

预览页不参与应用其他页面的玻璃背景采样：不使用 `layerBackdrop` 包裹 WebView，顶栏使用非玻璃样式，更多菜单也不采样页面背景。真机上 Chromium 在多层 `layerBackdrop` 捕获 WebView 时会反复出现 `tile memory limits exceeded`，导致正文瓦片被丢弃、闪烁或瞬间空白；打开更多菜单时尤其明显。普通顶栏和内容区不影响网页自身的渲染与交互。

**后果**：阅读器可以自行加载其页面、脚本、图片及任意内容 CDN，预览链接的可用性完全由当前镜像和阅读器决定。无法加载时保留刷新、复制公开图书链接和显式交浏览器打开；不退回到自行拼接阅读地址或下载文件。签名链接仍只存在于内存，不写入日志、导航参数、剪贴板或持久存储。`support@z-lib.bz` 等站方固定支持邮箱不能作为当前加载域名的判断依据。预览页顶栏与普通页面不同，不再呈现玻璃模糊效果。

## ADR-094：从详情将图书加入自己的书单，或新建并加入

**状态**：接受（2026-11-25）；仅扩展 ADR-079/084 的只读范围，设置中的「我的书单」仍为浏览入口。

**决策**：「加入书单」打开玻璃底部面板，一次读取当前账号拥有的书单及本书归属。点选未加入的书单才写入；已加入项有明确标记，点击不会移除。面板内可填写书单名称并「创建并加入」，使用一次携带本书 ID 的创建请求，明确创建私有书单。不恢复公开发现、书单搜索、收藏、编辑、删除或移除图书。

## ADR-095：书单选择器复用四封面卡片，评论分为列表与详情

**决策**：「加入书单」面板复用设置「我的书单」的四封面卡片，显示书单名称、已知图书数量和加入状态。优先使用归属响应中的数量和封面；不足时仅对可见卡片复用单内第一页接口取封面，最多两个并发，失败保留空位且不阻止点选。已加入的项不触发写入。新建表单移除说明小字，仍创建私有书单并加入当前图书。

## ADR-096：精简简介、在详情预览评论并恢复暂时性读取失败

**状态**：接受（2026-11-25）；调整 ADR-085/087 的简介布局及 ADR-093–095 的评论入口、回复呈现和读取重试范围。

**决策**：简介按实际排版最多显示五行，超出才提供下箭头「展开简介」与上箭头「收起简介」。按钮到上方正文与下方卡片边缘留白相同，长短简介均保留正文选择与复制。详情顶栏将「加入书单」图标放在收藏按钮左侧，保留原选择面板；移除出版信息下方的旧按钮组。

**读取重试**：仅图书评论、自己的书单、书单图书分页和本书归属这四类已记录的读取允许网络异常或 HTTP 502/503/504 时自动重试，首次之外最多三次、间隔 1/2/4 秒。每次使用原会话和镜像；切号、换域或取消时终止。验证、鉴权、限流、证书与协议错误不重试，达到上限保留手动重试。书单写入仍只发送一次，且所有 PAPI 请求继续拒绝重定向与验证 Cookie。

## ADR-097：在图书详情预览并浏览「延展书单」

**状态**：已被 ADR-099 取消（2026-11-25）；以下保留历史记录，不再授权接口或功能。原决定按用户要求参考 zlibx，新增包含当前图书的他人公开书单；其书页匿名及仅手动重试曾由 ADR-098 调整。

**决策**：详情的「查看更多评论」下方、出版信息之前增加「延展书单」入口及最多三张书单卡片。入口进入独立的延展书单页面；两处复用「我的书单」的四封面卡片，点卡片直接打开单内图书页。保留网站针对本书返回的顺序，不自行计算相关分；去重并剔除当前账号自己的书单和明确私有的书单。详情预览与独立页面共用内存中的同一份有限结果、可见封面和请求状态，返回保留列表及位置；公开单内页复用图书网格、分页、刷新和 app 回调导航。

zlibx 没有已确认的关联书单 JSON 接口，因此仅为本功能允许匿名读取当前镜像 EAPI 详情实际返回的 `/book/...` HTTPS 书页，不拼接网页短 hash、不跟随重定向、不接受 Cookie、不运行脚本或加载页面子资源。只解析 `.related-booklists-block` 中已预渲染的 `z-booklist` 及 `z-cover`；不提取其它元数据、不读取书单目录或书单 HTML 页面，不使用 WebView、挑战绕过或未知 loader 端点。书页必须有有效图书页标记；验证页、软 404、结构异常和网络失败作为错误，不能当作无书单。无该区块的有效书页才是正常空结果。当前账号书单仍经现有 PAPI 读取以剔除自有 ID；公开单内页与缺失封面的第一页补取匿名使用已有 `POST /papi/booklist/{id}/get-books/{page}`。所有请求限定在当前受信任 HTTPS 镜像，图片不携带凭据。

书页只读取一次有限结果，没有已核实的关联列表分页接口，不发送猜测的分页或排序参数。该 HTML 读取失败保留手动重试；不扩大 ADR-096 的自动重试范围。公开单内 PAPI 只读分页沿用该 ADR 的暂时性失败退避，写入行为不变。切号／换域取消旧读取并清空旧结果与选择；导航仅保存本书引用或公开书单 ID／显示标题，不保存 HTML、签名链接或账号凭据。私有书单继续在进入单内页时重新核对账号归属，不能借公开入口发送账号 Cookie。

**依据与验证边界**：zlibx 的 `book_detail_extras.dart` 记录了 2026-11-12 书页中已渲染的关联卡片及原顺序。本项目本次匿名 `POST /papi/booklist/2177510/get-books/1`、`/2` 在 `zlib.bz` 返回有效 JSON、20 本及递增下一页，其中图书 `id/hash` 可直接读取 EAPI 详情；不采用 zlibx 旧注释中匿名 GET 或缺少 EAPI hash 的假设。EAPI `href` 的网页短 hash 与 EAPI hash 不同。对五个镜像的匿名真实书页均遇到 HTTP 503 验证页，相关书单非空结果需用户在可用镜像验收；模拟 fixture 不代表真实镜像已通过。

## ADR-098：延展书单复用评论的会话传输与暂时性读取恢复

**状态**：已被 ADR-099 取消（2026-11-25）；以下保留历史记录，不再授权接口或功能。原修正针对用户真机反馈所有延展书单均失败、评论正常的情况，取代 ADR-097 的匿名书页及仅手动重试决定。

**原因与证据**：评论经 `PapiTransport` 携带当前账号的双 remix Cookie，延展书单却在请求书页前强制剥离全部账号凭据；匿名实际书页在多个镜像返回验证 HTML。zlibx 的关联区块与其它书页信息共用已登录请求管线，不是匿名读取。站点历史 `z-booklists-carousel.js` 虽包含 `GET /papi/book/{bookId}/related-booklists`，本次匿名请求均返回明确的 JSON 404，现代书页样本已经预渲染卡片；尚无当前可用的关联 JSON 及完整条目契约，不能将历史路径当作已验证替代接口接入。

**决策**：限定书页读取复用评论的 `PapiTransport` 请求构造、当前受信任 HTTPS 主机校验、双 remix Cookie、固定 UA、禁用缓存／重定向／底层重放和无 Cookie 存储的客户端。仅允许 EAPI 详情实际返回的当前镜像 `/book/...` href，无查询串、片段、userinfo 或非标准端口；不拼接网页 hash、不改写外部 href。书页只发送 `remix_userid`／`remix_userkey` 两个 Cookie，不发送其它 Cookie、EAPI remix／source 头或密码；不接受 Set-Cookie、不处理挑战、不运行脚本、不加载子资源。鉴权拒绝与评论一样在功能内提示，不使 EAPI 会话失效。公开单内分页和缺封面补取继续匿名，不因本 ADR 改为带凭据。

关联仓库仅对网络异常和真正的 HTTP 502/503/504 采用 ADR-096 的 1/2/4 秒退避，首次之外最多三次；每次绑定原账号／镜像，取消、切号或换域立即停止。检查非成功 HTTP 正文中的明确验证标记，包括 `Checking your browser`；验证、限流、认证、证书及协议错误不重试，不能把验证页当作空结果。归属过滤和会话检查继续保留，详情前三张与独立页面仍共享同份有限结果，不新增猜测的关联分页或接口。

**验证边界**：匿名失败、静态源码与模拟回归只证明协议差异和客户端行为，不能证明当前用户的登录态已经恢复。不得据此宣称已取得真实非空关联结果。本轮按用户要求不使用模拟器、不自动安装，完成单测、lint 与原签名正式通用包核验后交由用户真机验收。

## ADR-101：图书与自有书单生成图片分享

**状态**：接受（2026-11-25）；用户要求图书详情收藏右侧与书单详情顶栏增加分享，进入独立页面，预览图片并可保存或调用系统分享。

**决策**：app 统一承接两类分享入口并打开非导出的分享 Activity，feature 通过回调传递当前已加载的图书或自有书单与图书信息，feature 之间不互相依赖。分享图只包含图书封面、书名、作者、已知出版／文件信息和简介摘要，或书单名称、已知数量及前六本已加载图书的封面、书名和作者；不获取完整书单、不增加接口、不改变书单公开状态。书单超过预览数量或尚未完整加载时明确标注预览范围，不把已加载数冒充总数。每张图片最底部均居中显示软件当前图标和本地化名称。

图片采用固定清晰度的原生排版，预览与导出使用同一 PNG；缺失或失败封面使用本地书名／作者封面，缺失信息不造值，长文本有界排版，不截断底部标识。图片只加载已有封面地址，使用无会话、无 Cookie、无重定向的图片客户端。传入分享页面的有界内容快照不含会话、图书 hash、私有路径、阅读／下载签名链接或评论；不向外分享书单访问链接。

「保存到本地」通过系统创建文档选择位置，以 SAF 写入 PNG，不申请存储或相册权限、不加入下载队列、不建立本地书库。应用私有分享缓存仅保留有期限的图片；「分享」只通过独立 FileProvider 暴露所选单张图片，使用 `image/png`、`EXTRA_STREAM`、`ClipData` 和临时只读授权，由用户在系统面板选择接收软件。页面显示生成状态、重试及保存／分享失败的短提示；生成与文件 IO 在主线程之外执行，不自动上传或发送。

**验证边界**：覆盖内容有界化、书单预览数量、文件名与路径、图片导出及系统 Intent 的关键分支；执行单测、lint 和原签名正式通用包构建。不使用模拟器，真机保存与第三方接收仍以真实操作为准。

## ADR-102：域名发现与凭据授权分离

**状态**：接受（2026-11-26）；替代 ADR-065 中自动授信发现域的部分。

无凭据体检可探测重定向目标，始终使用该目标的标准 HTTPS `/eapi/info/domains`；探测结果归属于实际应答域。已知域名家族只说明接口兼容，不能证明未知域有权接收账号凭据。未知目标保留为发现提示，用户通过现有「添加域名」操作明确批准后才作为精确主机使用；旧版保存的发现项或锁定项不等于批准。锁定目标不可用时保留选择提示并提供更换入口，不以未批准目标代替当前可请求域名。

EAPI 发出请求前校验受信任的标准 HTTPS 来源（协议、主机、端口，不含 userinfo）；密码表单不跟随跳转，含凭据的请求不跨来源转发。图书 CDN 保持独立的无凭据传输边界，书单和评论仍使用既有同域 PAPI。Cookie 导入接受标准导出格式，按来源校验后只保留一组必要认证字段；旧会话保留有效的账号身份，清除其它转发 Cookie。在线预览读取结果必须属于发出时的当前会话及镜像；会话变化清除旧链接和网页，沿用 ADR-091 的开放阅读资源域名。

## ADR-103：验证同一下载内容并恢复未完成的文件交付

**状态**：接受（2026-11-26）；细化 ADR-006/011/049/060。

只对能用同一资源身份与强 HTTP 验证器确认的字节片段执行续传；签名 URL 不落盘。无可信验证信息、资源变更或旧版残留无法确认时，从零重写临时文件。响应字节范围、编码及长度仍须通过校验。鉴权、配额和网关故障按 EAPI 与无凭据文件响应分别解释，不以通用 CDN 拒绝判定账号过期。

最终文件交付与 Room 之间无法跨 Provider 使用同一事务。完成传输后，先持久记录待交付文件的任务与目录身份、目标和完整性证据，再改名或复制。未确认完成的目标不展示在本机书架；进程中断后优先核对现有文件并补记，只有可以确认属于本次下载的目标才重用或清理。无法可靠核对时保留可恢复状态，不覆盖用户文件或标成完成。本机目录优先监听变更，使用退避的定期扫描兜底；打开、分享和删除仍校验当前目录和精确文档归属。

图书和 APK 前台服务遵守 Android 对 `dataSync` 的共用时限；启动受限与系统超时需保留任务或明确显示可重试状态，并在系统期限内停止服务，不靠重启服务规避额度。

## ADR-104：公开更新信息可复用，分享失败可恢复

**状态**：接受（2026-11-26）；细化 ADR-056/101。

应用内更新仍匿名访问固定 GitHub 仓库。遵从服务端的限流重置时间，复用上次核实的发布信息，明确标示缓存状态，不能据缓存宣称已是最新版或提供应用内 APK 下载。限流时用户可打开同一仓库的 Releases；不增加 Token、代理或后台轮询。

分享图为封面加载设置整张图的等待上限，超时的封面使用本地占位，预览和导出仍为同一结果。SAF 保存失败或取消后，仅对本次创建的目标尝试清理；无法清理时提示用户检查目标，避免把空文档当成有效导出。

## ADR-105：更新网络失败用短提示，限流等待按当前网络区分

**状态**：接受（2026-11-26）；细化 ADR-055/056/104。

GitHub 未认证 API 的主限额按出口 IP 共享；使用 VPN 时，多个用户可能共用已耗尽配额的出口，也可能遇到连通性问题。客户端不能从失败断定用户正在使用 VPN。手动检查更新或读取更新日志遇到连接失败、明确的 GitHub 限流时，统一使用系统短 Toast「网络环境异常，请关闭或开启 VPN 后重试。」；检查更新不弹错误面板，启动检查失败保持静默。日志保留已有内容或中性失败状态、手动重试及固定 Releases 入口；展示缓存时明确标记，不提供应用内下载。其他发布响应错误保持原行为。

最新版本和历史查询在同一个 Android 默认网络上继续共享服务端给出的等待时间。Android 确认可用的默认网络变化时，新网络可以按原有入口请求，不抹除旧网络尚未到期的等待；无法判断网络时不据此跳过等待。应用不监测外部 IP、不检测或切换 VPN、不因网络变化自动请求，也不引入认证、代理或轮询。任何网络遇到服务端限流均遵从响应。

## ADR-106：内置可选镜像不等于内置授信

**状态**：已由 ADR-107 取代（2026-11-26）；保留原决定作为历史记录，凭据授权原则仍沿用 ADR-102。

从用户指定的 `zlibx-ref`（`a4c9f13` 的 `lib/providers/domain_provider.dart`）选取本次匿名 HTTPS `/eapi/info/domains` 返回有效 JSON 的 22 个新域名，保留参考项目顺序。不复用其认证、动态目录或自动授权策略。匿名探测只说明当时兼容，不保证域名由 Z-Library 运营，也不保证此后可用。

候选在「域名管理 → 添加域名」可点选填入主机；未登录时也能从登录页「更换域名」找到，并在确认后添加和切换。启动体检无可用域名时，也能从更换入口点选填入，仍须明确点击「添加并重试」。添加前说明镜像可能读取发送给它的密码和会话凭据。候选不加入内置可信域、冷启动体检或自动切换；仅在用户明确添加后，沿用精确主机授权，才能体检、切换和使用，不隐式信任子域。移除自定义域名会撤销该授权，仍可日后重新明确添加。

## ADR-107：官方与社区镜像直接列入域名管理

**状态**：接受（2026-11-26）；按用户要求取代 ADR-106 的候选界面，保留 ADR-102 的凭据授权边界。

设置、登录和启动失败恢复中的镜像列表统一分为「官方镜像」与「社区镜像」。保留既有 16 个官方域名，增加有团队公告依据的 `z-library.gy`；社区组直接内置参考项目经 VPN／直连任一路径成功的 33 个精确主机，以及团队定制镜像公告中的 `libb.la`，共 17 个官方、34 个社区。参考项目全部 41 个域名均重新做匿名双线路检查，两条线路都失败的七个域名不进入新增目录。两组使用相同的体检与切换卡片，不再提供候选添加列表。

官方分类依据既有目录和团队公告，社区兼容性测试不构成运营方认证。社区镜像无需手动输入添加；首次选择时说明其能接收密码和会话凭据，用户确认后保存精确主机授权。已授权社区镜像与官方域名使用相同的手动／自动切换机制；撤销授权后保留内置卡片。体检始终不带账号凭据，匿名成功不自动授信。用户触发的全部体检覆盖整个目录；启动和故障恢复只探测官方、当前及已经批准的镜像，局部体检合并结果，不隐藏未检查卡片。内置目录中的精确应答主机可以使用空 `domains` 的有效 EAPI 响应；未知跳转目标仍需域名家族检查与单独明确授权。

## ADR-108：隔离网页供用户完成人机验证

**状态**：接受（2026-11-26）；按用户明确要求，为 ADR-066/088/091 增加仅限域名人机验证的 WebView 例外。

点击标记为 DiamWall／网页验证的已授权镜像时打开应用内独立验证页，由用户完成原站挑战。验证页使用非导出的独立进程 Activity 和独立 WebView 数据目录，避免图书预览清理 Cookie 干扰验证；不向网页注入账号 Cookie，不提供账号登录或 Cookie 导入，不抓取网页或自动求解挑战。主页面与资源只允许所选主机的标准 HTTPS 请求，不忽略证书错误，不允许文件、内容 URI、混合内容、弹窗或网页下载。

验证页面使用独立匿名传输逐跳校验同源，只支持 GET／HEAD，最多五次跳转，请求链限时 25 秒、单资源最多 8 MiB。保留原站 CSP 并叠加同源资源限制；关闭跨域、表单、worker 和登录路径。513 等挑战响应仍交给 WebView 渲染 HTML／脚本，不自动求解。此约束可能使部分挑战不兼容，TLS 指纹亦可能影响结果。

用户明确点击完成后，仅回传有界的 `__diamwall` 验证 Cookie 和验证时的系统网络标识，网页中的其它 Cookie 全部丢弃。主进程再次核对精确主机授权及网络身份，验证 Cookie 仅在内存中按主机和当前系统网络保存最多 15 分钟，并只发送至同一主机的 EAPI／匿名域名体检。PAPI、封面、阅读预览、CDN 和 GitHub 不接收此 Cookie；跳转不能恢复验证或账号凭据。返回后的授权检查、原主机体检及选择在同一个域名仓库锁内完成，只有原主机 EAPI 确认可用才完成本次选择；未通过时提示重试或换域，不将网页加载完成冒充验证成功。退出清理验证页 Cookie，进程重启与切网后重新验证；主进程仅为清理临时验证状态监听系统默认网络，不因此发出请求。实际能否解除挑战须以用户真机、出口及 WebView 为准。
